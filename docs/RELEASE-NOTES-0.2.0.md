## 0.2.0 新增：图形界面

**双击 exe 就有窗口**，不用再记命令行。

| 页面 | 能干什么 |
|---|---|
| **运行** | 看状态、启停监听、按住热键说话、**打字试一句**（走完全相同的链路，只是跳过录音） |
| **日志** | 实时事件流，按级别/关键字过滤、暂停、导出；同时写一份到 `voice-ctl.log` |
| **快捷键** | 点一下、按下组合键就录好了；自动拦掉 `Ctrl+Space`（输入法）、`Alt+F4` 这类被系统抢走的组合 |
| **功能** | 列出所有动作和它们的「说法」，逐个显示「现在能不能跑通」；改说法、改目标、增删、试运行 |
| **设置** | 麦克风、静音阈值、匹配阈值、语义层——都带一句「这个值为什么是这个数」；**模型也能在界面里下载** |
| **关于** | 路径、依赖版本、一键完整体检，出问题直接把结果复制到 issue |

界面用的是**标准库自带的 tkinter**，不额外背 Qt/Electron，打包后只多 3.2 MB。

### 这一版专门解决的三件事

1. **保存只改你改过的那几行。**
   点保存不会把 `config.toml` 重写一遍——注释、空行、你自己偏好的写法
   （`0.010` 不会被改成 `0.01`）全部原样保留，并留一份 `config.toml.bak`。
   反复点保存不产生 diff。

2. **写不出来的配置就不写。**
   每次保存前都会把改完的配置**真的加载一遍**；加载不了就整个放弃写入，
   你的文件一个字节都不动，并告诉你哪一行不对。
   （开发中真踩过一次：点「新建动作」写出了既没说法也没目标的动作，
   语法完全合法、加载却失败，结果下次启动直接起不来。）

3. **识别不再跑在键盘钩子线程里。**
   pynput 的回调就是 Windows 的低级键盘钩子过程。整条「识别+执行」实测
   100–250ms，超过系统的 `LowLevelHooksTimeout`（默认 300ms）后 Windows 会
   **悄悄摘掉钩子**——表现是「按几次之后热键忽然没反应了」，而且日志上什么
   都看不到。现在钩子线程只做状态转移，识别丢给一条单工作线程。

另外：热键改成在界面上录制（自动拦截被系统占用的组合），改完即时生效，
不用重启程序。

## 下载哪个

| 文件 | 体积 | 首次使用 | 启动 |
|---|---|---|---|
| **`voice-ctl-0.2.0-win64-lite.exe`** | 58.1 MB | 界面里点「下载识别模型」（226MB） | **1.7s** |
| `voice-ctl-0.2.0-win64-full.exe` | 210.1 MB | 开箱即用 | 3.1s |

**推荐 lite**——多下一次模型，但每次启动快一倍。`full` 内嵌了模型，代价是每次运行都要把 226MB 解包到临时目录。

两者功能完全一致，只差模型是否内嵌。

## 快速开始

```powershell
# 直接双击就行 —— 打开界面，在「设置」页下载模型，在「运行」页点启动。
.\voice-ctl-0.2.0-win64-lite.exe

# 自检：确认依赖、原生 DLL、界面、模型、麦克风都正常（不碰麦克风，安全）
.\voice-ctl-0.2.0-win64-lite.exe --selftest

# 命令行也还在
.\voice-ctl-0.2.0-win64-lite.exe doctor
.\voice-ctl-0.2.0-win64-lite.exe run     # 不开界面，常驻监听（适合开机自启）
```

跑起来后**按住 `Ctrl+Alt+Space` 说话，松开执行**。

不需要装 Python，单文件 exe。

## 环境要求

- Windows 10/11 x64
- 一个能用的麦克风
- 首次使用需要联网（下载模型），之后完全离线

## 首次使用必读

- **热键是 `Ctrl+Alt+Space` 而不是 `Ctrl+Space`**：中文 Windows 上
  `Ctrl+Space` 是输入法切换键，会被系统抢走。想换成别的，在「快捷键」页点一下
  再按组合键即可。
- **没装代码签名证书**，首次运行 Windows Defender SmartScreen 会拦一下，
  点「更多信息 → 仍要运行」。
- 精简版要先在「设置」页点「下载识别模型（约 226MB）」，进度打在日志页。

## 已知限制

- **未做代码签名**，SmartScreen 会提示。
- **准确率数字来自 TTS 合成语音**，与真人说话有差距。仓库里的端到端基准是
  18/18 命中，但那是合成音，别当真人指标。
- **界面在无图形环境（服务器核心、部分远程会话）下打不开**，此时命令行功能
  全部照常可用（`run` / `doctor` / `simulate` / `test`）。
- **热键靠 Windows 低级键盘钩子实现**，会和同样用钩子的程序（部分录屏、
  远程控制软件）冲突，症状是时灵时不灵——换个组合键通常就好。
- **语义层（第 1 层）默认关闭**，需要额外下载约 900MB ONNX 权重。它只该兜住
  别名匹配漏掉的口语化表达，不该当主判据。

## 技术细节

- 识别：sherpa-onnx 1.13.8 + SenseVoice int8（CTC），纯 CPU，RTF≈0.04
- 界面：tkinter（标准库），自绘深色主题，DPI 感知，深色标题栏
- 事件：自建事件总线，控制台/文件/界面三个 sink，emit 微秒级返回
- 配置回写：保留注释的定点 TOML 改写 + 写前语义校验
- 413 个单测（含真实建窗的界面冒烟测试），不需要麦克风也不需要真权重
