# voice-ctl 0.3.6：界面重做

按住快捷键说话 → **本地离线**识别 → 理解整句话 → 执行。全程不联网、零调用成本。

这一版把界面整个重做了，另外修掉一个**打包版一开界面就崩**的缺陷。

## 一、界面重做

原来那套是"能用的 tkinter 默认外观"：灰底、ttk 主题色、控件堆叠。功能没问题，
但看不出这是个什么东西。现在立了一个明确的视觉身份——

**一台「按住说话」的设备的控制面：浅色机壳承载控件，深色屏幕承载机器输出。**

```
┌──────────┬────────────────────────────────────────┐
│  品牌    │  ┌──────────────────────────────────┐  │
│          │  │  未启动          [Ctrl][Alt][空格]│  │  ← 深色屏幕
│  运行 ●  │  │  ···· 点阵电平 ····              │  │
│  日志    │  │  [打字试一句…]          [发送]   │  │
│  快捷键  │  └──────────────────────────────────┘  │
│  功能    │   ▶ 开始监听   ⤓ 加载识别模型   ● 21 个动作 │  ← 机壳上的控件
│  设置    ├────────────────────────────────────────┤
│  关于    │  最近一次                    识别 0 成功 0 │
│          │  ┌──────────────────────────────────┐  │
│   ⏻     │  │                                  │  │
└──────────┴────────────────────────────────────────┘
```

几条定下来的规矩（都写进了 `theme.py` 的注释，改版时不要随手破）：

| 规矩 | 理由 |
|---|---|
| 信号橙 `#FF5B1F` **只**表示"正在录音" | 它一出现就是麦克风开着。不做装饰用 |
| 青 `#087376` 表示就绪与焦点 | 和橙拉开语义距离，不会看混 |
| 屏幕底 `#0F1416`，比纯黑偏青 | 纯黑在浅色机壳上会"糊"成一块洞 |
| 圆角按角色区分（屏幕 22 / 面板 16 / 输入框 10 / 键帽 8） | 一刀切的圆角是"模板感"的头号来源 |
| 发丝线代替阴影 | Tk 没有真正的模糊，假阴影比没有更廉价 |

### 自己写了一套绘制层

Tk 画不了渐变、抗锯齿圆角、图标，而这套视觉语言需要的正是这些。所以新增了
四个模块（约 2200 行），**不引入任何新依赖**——只用已经装了的 numpy：

| 模块 | 行数 | 干什么 |
|---|---|---|
| `ui/gfx.py` | 454 | 距离场抗锯齿光栅器、键帽、图标、点阵、PNG 编解码 |
| `ui/kit.py` | 976 | 控件库：面板/卡片/按钮/开关/下拉/分段/药丸/提示条 |
| `ui/inputs.py` | 763 | 输入类控件：文本域、滑块、下拉弹层、数字步进 |
| `ui/textfit.py` | 76 | 中文换行的**避头尾**（标点不掉行首、开括号不掉行尾） |

`textfit.py` 那个是必须自己写的：Tk 的 `wraplength` 只认空格，中文整段没有空格，
它就在放不下的那个字处硬断，结果常常是**一行末尾只掉下来一个「。」**。这在排版上
是错的，而且一眼就能看出来。

绘制层是纯 numpy，量字宽的函数从外面传进来，所以**能直接单测**——不需要 Tk、
不需要图形环境。这也是为什么 `test_ui_gfx.py` 的 85 个用例能在 CI 里跑。

### 六页全部重写

运行、日志、快捷键、功能、设置、关于。运行页有六种状态各自的表情：未启动/待命
（青光慢扫）/录音（大字变橙、键帽下沉变暖、橙色声波滚动、侧栏电源键同步变色）/
识别中/出结果/出错。

极限尺寸也调过：最小窗口（980×640）下侧栏自动进入紧凑模式收起文字，控制条放不下
就换行而不是被裁掉。

## 二、性能：切设置页从 3440ms 降到 622ms

重做之后逐项量了，发现两个真瓶颈：

**① 切到设置页要 3.4 秒。** 原因是 `decision.available()` 为了判断"这台机器能不能用
语义层"会**真的 import torch**（几秒），而它原来是在 UI 线程里调的。现在整个
"预检 → 下载"都在后台线程，并用 `ui/workers.py` 里的 `HEAVY_IMPORT_LOCK` 串行化。

**这把锁不是可有可无的**，它挡的是一个实测到的死锁：

```
后台线程 import torch（几秒，期间 GC 随时会跑）
  → GC 回收到某个 tkinter 对象（PhotoImage/StringVar/Font，它们的 __del__ 要调 Tcl）
  → 非主线程调 Tcl 会被转发给主线程并**阻塞等待**
  → 而主线程若正好卡在同一个 import 锁上
  → 两边互等，永久卡死
```

所以铁律是：**主线程只跑事件循环，从不等后台线程**；重量级导入只在持有那把锁的
后台线程里发生。

**② 点阵电平表每帧 47ms**（超过 33ms 的帧间隔，录音时会卡）。原因是按点逐个重画。
改成"一张图 + 按需写入"后降到 3.1ms，快 15 倍。

同机同脚本实测（i7-13650HX，CPU 推理）：

| 指标 | 重做前 | 重做后 |
|---|---|---|
| 切到设置页 | 3440 ms | **622 ms** |
| 切到功能页 | 527 ms | 483 ms |
| 空闲 CPU（未启动） | 1.6% | **0.8%** |
| 录音态 CPU（~30fps） | 12.9% | **5.9%** |
| RSS（灌 4000 条日志后） | 320 MB | **154 MB** |
| 控件总数 / PhotoImage | — | 625 / 145 |

## 三、修掉：打包版一开界面就崩

```
✗ 图形界面建不起来: AttributeError:
  module 'voice_ctl.ui.theme' has no attribute 'apply_dark_titlebar'
```

界面重构把 `theme.apply_dark_titlebar` 改名成 `apply_titlebar`，`window.py` 跟上了，
**`exe_entry.py:113` 没跟**。

为什么源码运行和全部单测都发现不了：`exe_entry.py` 只在打包入口里跑，
**没有任何测试 import 它**。症状是"窗口一闪就没了"，用户完全无从反馈。

修法是一行。真正留下来的是守卫：新增 `tests/test_no_stale_attrs.py`，静态扫
`voice_ctl.<mod>.<attr>` 形式的跨模块引用（AST 算出模块的顶层名字表，不 import、
避免副作用），属性对不上就红。只查静态算得准的部分，运行时 `setattr` 的一律不报
——宁可漏报也不误报。

反向验证过：把那一行改回旧名字，守卫立刻红并点名
`exe_entry.py 用了 theme 里不存在的属性：['apply_dark_titlebar']`。

## 四、顺带补上的测试守卫

* **`tests/test_spec_ui_modules.py`**：界面模块漏出 `voice-ctl.spec` 就红。
  界面是延迟 import 的，PyInstaller 的静态分析扫不到它下面的子模块，必须在
  `hiddenimports` 里显式列出。漏一个的表现是"源码跑得好好的，打包后切到某一页
  就 ImportError"，而且报错不指向 spec。双向检查（漏列会红、列了但文件已不在也红）。
* **`tests/test_ui_gfx.py` / `test_ui_textfit.py`**：绘制层与折行的纯函数测试，
  不需要图形环境。

## 五、已知问题：语义层的置信度不可靠

这一版**没有动**语义层（Laya ONNX），但 0.3.4 量出来的问题依然存在，再写一遍
免得有人以为界面重做顺便修好了：

在 21 个候选动作的真实配置下，它的**置信度和正确性不相关**——真该命中的
「我想聊个天」只有 0.153，不该命中的「这个多少钱」是 **1.000**（真的会开 B 站）。
所以 `[decision].enabled` 仍然默认 `false`，任何阈值都拦不住后者。

好消息：句首否定是安全的。「不要打开计算器」「别关微信」在意图层就被拦下，
走不到语义层。

### 另外记一笔：试过但撤销的改动

想给深色屏幕加"上亮下暗"的渐变描边（大面积深色平涂确实显得像死塑料）。
技术上可行——`gfx.Layer.paint()` 收逐像素颜色。试了三轮都失败：

* 渐变图与角块的取样口径不一致 → 顶/底出现与四角不同的色带
* 把全高的图铺在顶边 → `y..y+r` 那一整片被刷成描边色（截图量到整片 `(40,52,56)`）
* 改用 1px 高的整条渐变图 → **Tk 会把它按 item 显示高度纵向拉伸**，
  1px 的线变成 35px 的粗横杠

根因是 `Panel` 的 body 是不透明 Frame、铺满内部，渐变唯一能露出的地方只有描边，
而描边在 Tk 里做渐变没有可靠做法。**全部回退**，界面保持原样。

留个教训：`RoundedBg` 把面板拆成"四个角用图 + 边和中间用色块"，好处是面板缩放
只挪几个坐标、不重画整张；代价是**任何需要"连续变化"的效果（渐变）都做不了**，
因为中间那段是纯色矩形，画不了渐变。
