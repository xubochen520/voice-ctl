# voice-ctl 0.3.5：修掉「从界面点下载，906MB 白下」

按住快捷键说话 → **本地离线**识别 → 理解整句话 → 执行。全程不联网、零调用成本。

这一版只修一个缺陷，但它是用户实际撞到的，而且**0.3.4 那次修复遗漏了它**。

## 缺陷：界面那条路径没被修到

0.3.4 我修了 `voice-ctl fetch-decision`：这个构建加载不了语义层时，
**下载之前**劝阻（精简版没带 torch，下完也用不了）。修完验证过，过了。

**但只修了 CLI 那一半。** 界面「设置」页有个「下载语义层权重（约 900MB）」按钮，
走的是 `tab_settings.py` 里**另一份**代码，直接调 `fetch_weights`——没有那道检查。

用户实测（0.3.5 的来由）：

```
19:43:18 OK    [engine] 就绪：21 个动作，热键 <ctrl>+<alt>+space，仅别名匹配
19:43:49 INFO  [download] 开始下载语义层权重 multilingual（约 900MB…）
          ...  906MB 下完
```

他跑的是 `voice-ctl-0.3.4-win64-full.exe`（完整版，**不带**语义层）。
下载位置旁边因此多了个 906MB 的 `models\` 目录。开语义层后：

```
⚠ 语义层启用失败：这个精简版 exe 没带语义层（No module named 'torch'）
```

**906MB 白下。** 这是 0.3.4 已经承诺要防住的事，只是防漏了一半。

## 根因：同一件事有两份实现

| | 构建能力检查 | 落盘路径 |
|---|---|---|
| CLI `fetch-decision` | 0.3.4 补上 | 0.3.4 补上 |
| 界面「设置」页按钮 | **没有** | **仍是原始相对字符串** |

而且界面那份的落盘路径还有一个 0.3.4 已经在 CLI 里修过的同类缺陷：
它用 `self._onnx_dir.get()` 的**原始字符串**去 `mkdir`。那是相对路径，
相对**配置文件所在目录**才对，直接拿去创建会相对**当前工作目录**——
用户从 `C:\Windows\System32` 里点一次，906MB 就下到那儿去了。

**两份实现，各漏一半。** 这是最难查的那类缺陷：修了一处、验证过了、
另一处还在。

## 修法：把判断抽成一份

新增 `decision.preflight_fetch()`，CLI 和界面**共用**它。它一次做完三件事：

```
1. 已经有了（内嵌的，或先前下好的）  -> already_ready，别下
2. 这个构建根本加载不了语义层        -> allowed=False，别浪费 906MB
3. 落盘位置                          -> 绝不返回相对路径
```

返回一个 `FetchPlan`，两边按各自的界面形式呈现：

- CLI：打印 + `input()` 询问「仍然下载？[y/N]」，`--force` 跳过
- 界面：**直接拒绝**，不弹对话框。点一个按钮就该是有效动作，
  弹「要不要继续」然后照样下 906MB 算不上保护

判据用 `available()` 的返回语，不靠猜：以「缺少」开头的是**权重文件不在**
（下载能解决），其余都是**这个构建缺依赖**（下载解决不了）。

## 顺带修的：`--dir` 之外的落盘语义

`preflight_fetch` 里那段路径逻辑值得单独说，因为它的正确性不显然：

```
配置是绝对路径            -> 原样用（用户显式指定）
配置是相对路径            -> 取它的**目录名**，挂到可写数据目录下
   models/laya-onnx/multilingual  ->  <data>/models/laya-onnx/multilingual
```

为什么取末段而不是整条拼：配置里的相对路径是相对**配置文件所在目录**解析的，
而配置文件就在数据目录下（打包后首次运行会复制到 exe 旁边）。
所以 `<data>/models/laya-onnx/multilingual` 正好等于配置解析出来的位置——
下载到哪里，运行时就从哪里读。

有一条测试专门守这个：随便喂什么相对路径，`plan.target` 都必须是绝对路径。

## 你现在那 906MB 没白存

`C:\Users\29329\Downloads\models\laya-onnx\multilingual` 里的权重是**好的**，
只是那个 exe 用不了。换 `semantic` 那个包就能用上——把它解压到
`Downloads` 下，配置里的相对路径正好落到你已下好的那份上，不用重下。

（`semantic` 包自己已经内嵌了一份同样的权重，所以其实也不必用你这份；
留着或删掉都行。）

## 升级注意

- 不需要改配置。
- 完整版和精简版**依然加载不了语义层**——它们没带 torch。
  这不是缺陷，是体积取舍（torch 约 500MB）。要用语义层请用 `semantic` 包。
- 语义层在内嵌权重的包里**仍然默认关闭**（原因见 0.3.4 版本说明第四节的实测表）。

## 实测

| 项 | 结果 |
|---|---|
| 复现用户场景 | 完整版 + 那 906MB + 语义层开启 → `No module named 'torch'`，确认白下 |
| 界面拦截 | 构建加载不了时直接拒绝，不再下载；真包实测回答 `n` 后**没建目录、一个字节没下** |
| 落盘 | 喂 5 种相对路径（含空串），产出全是绝对路径 |
| 新增单测 | 12 个（preflight 6 + CLI 4 + 界面 5，其中两条守"别再把判断分叉出去"） |
| 单测总数 | **1106 个通过，2 跳过**（约 53 秒） |

### 写这批测试时踩到的两件事，记下来免得重复

**一、`EventBus.close()` 是不可逆的。** 它把 `_closed` 永久置真
（`events.py:213`），而 conftest 的 `app` fixture 每次 teardown 都会 close
那条 module 级总线。于是同一个文件里**只有第一个测试**能收到 sink 派发，
后面的全哑——表现为"单跑通过、一起跑必挂"。

界面本来就是**轮询** `bus.since(seq)` 消费事件的（不依赖后台线程），
所以测试也改成轮询，既绕开这个坑，又更贴近真实用法。

**二、"碰巧通过"的测试比没有更糟。** 有一条 preflight 测试原本写的是
"内嵌权重 -> 应当标 bundled"，它**通过了**——但原因不对：本仓库里真实存在
`models/laya-onnx/multilingual`，兜底第一条（配置目录存在）就命中了，
压根没走到内嵌那条分支。现在直接把 `resolve_decision_dir` 的返回值钉死，
逼它走内嵌路径。
