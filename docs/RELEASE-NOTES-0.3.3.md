# voice-ctl 0.3.3：说得出名字的网站就能开，说错了能收回

按住快捷键说话 → **本地离线**识别 → 理解整句话 → 执行。全程不联网、零调用成本。

这一版加了三件事，都是"用户说了人话，程序该听懂"的那一类：

- 说「打开百度网页」「打开百度官网」「打开淘宝」→ **打开对应网站**
- 说「打开百度网盘，呸」→ **什么都不做**
- 说「打开浏览器并且打开百度页面」→ **两件事都做**（以前后半句无声消失）

## 一、打开网站

以前这两句是错的：

```
打开百度网页  →  未命中: 动词是打开，但没找到叫「百度网页」的应用
打开淘宝      →  未命中: 动词是打开，但没找到叫「淘宝」的应用
```

原因很直接：别名匹配和已安装应用索引都只认**本机装了什么**。而「百度」「淘宝」
说的是网站，本机没装它们的客户端完全正常——于是什么都不做。

现在加了一层站点解析（`voice_ctl/web.py`），**约 70 个常见站**写在内置表里：

| 说法 | 打开 |
|---|---|
| 打开百度 / 百度网页 / 百度官网 / 度娘 | baidu.com |
| 打开B站 / 哔哩哔哩 / bilibili | bilibili.com |
| 打开淘宝 / 淘宝网 / 京东 / 拼多多 | 对应站点 |
| 打开12306 / 火车票 | 12306.cn |
| 打开 github / 码云 / 知乎 / 微博 / 豆瓣 | 对应站点 |
| 打开 example.com | 直接当域名开 |

覆盖搜索门户、购物、视频、社交、工具、邮箱、出行、游戏等各类常见站。
站点表**不联网**——查表是毫秒级的字符串比较。

### 三层解析，顺序是刻意的

```
站点表  →  看起来像域名  →  搜索兜底（可关）
```

**搜索兜底排在最后**，因为它总能给出一个结果，一旦排前面就会把所有"其实该打开
本地程序"的名字也吞掉——「打开计算器」会变成搜索"计算器"。实测过的旧缺陷正是
这一类：说「打开QQ音乐」而没装，`open.browser` 以 0.633 勉强命中，**真的打开了
一个必应窗口**，跟用户要的毫无关系。

现在「打开QQ音乐」有了正确的去处：QQ 音乐没装，但它的网站存在 → 打开 y.qq.com。
这不是勉强命中，是同一个东西的网页版。

### 本机程序 vs 网站：谁赢

这台机器上装着「百度网盘」，所以「打开百度」有个真实冲突。判据是**用户说的名字
有多确切**，不是谁分高（两边的分数量纲不一样）：

| 说法 | 结果 | 为什么 |
|---|---|---|
| 打开百度 | **baidu.com** | 站点表把「百度」确切命中。本机是「百度网盘」（模糊 0.72）——用户说的不是它 |
| 打开百度网盘 | **本机网盘程序** | 说的名字和那个程序一模一样 |
| 打开百度网盘，呸 | **什么都不做** | 用户自己收回了 |
| 打开微信 | **本机微信** | 站点表里没有微信，本机是配置动作确切命中 |
| 打开计算器 | **本机计算器** | 站点表里没有 |
| 打开百度官网 | **baidu.com** | 用户点明了要网页，本机同名程序让位 |

「确切」还分三档，这个区分是必需的：

```
exact     名字本身就是站点名/别名      → 「百度」「B站」「12306」
suffix    剥掉一个弱尾巴后恰好是站名    → 「淘宝网」（网是弱尾巴）、「中国天气网」
contained 名字里带着站点名             → 「百度糯米」——不算确切
```

**弱尾巴只有「网 / 网站 / 官网 / 网页 / 主页 / 首页」，「网盘」不在里面。**
这是实测踩出来的：「百度网盘」是另一个站（pan.baidu.com），把「网盘」当尾巴剥掉，
「打开百度网盘」就会开成百度首页。

### 关得掉

```toml
[web]
enabled = true          # 关掉就退回旧行为
search_fallback = true  # 唯一会让语音指令联网的开关
search_url = "https://www.baidu.com/s?wd={q}"
```

`search_fallback` 是**唯一联网**的一步，界面「设置」页有开关。彻底离线用就关掉，
站点表本身不联网，「打开百度」照样能用。

## 二、说错了能收回

用户亲口给的用例：**「打开百度网盘，呸」不该打开网盘。**

这是最伤信任的一类缺陷——用户刚说完"不要"，程序却执行了。以前的行为：

```
打开百度网盘，呸  →  ✓ 已启动 百度网盘
```

现在认出「呸」「不对」「说错了」「口误」这类自我更正，两个方向：

| 说法 | 结果 |
|---|---|
| 打开百度网盘，呸 | **整句作废**（标记在结尾） |
| 打开百度，不对，打开淘宝 | **打开淘宝**（改口了，用后面那条） |
| 打开百度不对打开淘宝 | 打开淘宝（ASR 常常不给逗号，所以不能只看标点） |
| 呸 / 不对 / 说错了（单独一句） | 作废（被听错之后最常见的反应） |

### 难点全在"别误伤"上

中文里「不对」出现在正常命令里毫不稀奇。把这种句子作废掉，用户会觉得程序在乱猜。
所以这一层的每一条规则都配了反向用例：

| 说法 | 结果 | 为什么 |
|---|---|---|
| 提醒我不对账 | **照常建日程** | 「不对」夹在正文里，后面没有新命令 |
| 打开微信，算了 | **照常打开微信** | 「算了」不在撤回词表里——见下 |
| 别打开计算器 | 照常不执行 | 这是否定，不是撤回 |
| 打开百度网盘 | 照常打开网盘 | 没有标记 |

**「算了」「取消」刻意不在撤回词表里**，这是量过的：「打开微信，算了」的切分结果
是 `['打开微信', '算了']`，把它当撤回就会把「打开微信」这条正常指令吃掉。这两个词
在 `NO_WORDS` 里是对的（那是对**确认卡**的回答），但当整句的尾巴时判断不稳。
宁可少收回一次，也不要误伤。

另外「说错了」比看上去难：它会被拆成「说错」+残余的「了」，而那个「了」不是命令。
只判"标记后面还有字"的话，整句会变成一条叫「了」的新命令——用户说什么都执行不了。
所以改口成立的判据是"后面必须跟着**真命令**（以开关动词开头）"。

## 三、一句话里两件事

翻日志时看到的：

```
听到  : "打开浏览器并且打开百度页面"
命中  : open.browser  via intent (score=0.94 alias-hit alias='打开浏览器')
执行  : ✓ 已打开 https://www.bing.com
```

「打开百度页面」这半句**没有任何提示地消失了**。用户以为程序没听见，其实是听懂了
却丢掉了——这比明确报错更糟。

现在按连接词拆开，逐条执行、逐条报告：

```
拆分  : 听出 2 件事 —— 这句话里听出 2 件事，都做完了
  1. 「打开浏览器」
     open.browser —— ✓ 已打开 https://www.bing.com
  2. 「打开百度页面」
     open.web —— ✓ 已打开 百度
```

### 拆分规则做得很保守

失败方式不对称：

- **少切一刀**：后半句没执行，但前面那句是对的，用户至少看到了部分效果
- **多切一刀**：把一条正常指令劈成两条读不懂的片段，**两件事都做不成**

所以：连接词只有「并且 / 然后 / 接着 / 还有 / 顺便」这少数几个，
**「和」「跟」「以及」刻意不在表里**——它们在名字里出现的概率太高
（「哔哩哔哩和它的朋友们」是一个名字）。而且切完每一段还得**像一条命令**
（以开关动词开头）才认。

| 说法 | 结果 |
|---|---|
| 打开浏览器并且打开百度页面 | 两件都做 |
| 打开记事本然后打开计算器 | 两件都做 |
| 打开记事本，然后打开计算器 | 两件都做（标点不影响） |
| **打开记事本和计算器** | **不拆**（「和」不在表里） |
| 打开浏览器并且很快 | 不拆（后半段不像命令） |

一件成一件败时，整体**报失败**并说明几件成了——不能让用户以为都做成了。

## 升级注意

- 不需要改配置。新增的 `[web]` 段都有默认值，`enabled` 是 `true`。
- `[[action]] open.web` 需要**手动加**（或让界面「设置」页保存一次自动补上）——
  没有它时意图层仍然认得出网页意图，但会回落到别名匹配，行为和以前一致。
- `[web].search_fallback` 会让语音指令联网。介意就设成 `false`。
